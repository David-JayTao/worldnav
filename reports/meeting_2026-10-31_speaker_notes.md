# WorldNav 逐页讲稿（约 6～7 分钟）

## 第1页

今天先用三页介绍 WorldNav 是什么，再汇报我们实际完成的工程和模型实验。任务的关键是，机器人只能看一张起始图片，然后根据一句自然语言指令，预测接下来整段路线。我们使用远程视觉语言 API 建立零样本策略，所以本地没有 GPU 也可以开展实验。但这条路线不是官方 LCVN 模型复现，下面会把二者明确区分。

## 第2页

可以把任务想象成：我们把机器人放在一条小路或走廊里，只给它眼前这一帧，再告诉它往前走、经过一个地标、向右转、到某处停止。模型既要看懂环境，也要理解指令中的先后关系。开放环的意思是，走起来以后，它不会获得真实的新图片来纠正错误。因此，开始时对距离或者转弯位置的一点误判，可能沿着整条路线累积。

## 第3页

模型的输入始终只有图像和指令。输出是一个数值列表，每一项有三个量：向前移动多少、向左移动多少，以及朝向改变多少。这里的坐标随机器人当前朝向变化，不能把世界坐标的位移直接填进来。一条动作先执行平移，再更新角度。模型自己决定输出多少步，列表结束就表示路线结束，而不是把全零动作当作一个特殊停止标记。

## 第4页

只走到终点附近还不够，比赛还关心整条路线是否正确。SR 是终点成功率；ATE 和 RPE 分别看位置和步间移动误差；F 看完整路径，H 看朝向和转弯。最后逐样本组合成分数。我们直接调用固定版本的官方公开实现，没有自行改写这些指标。但服务器私有评分环境没有开放，所以现在应称为公开指标评测，不能直接当作排行榜成绩。

## 第5页

我们的链路是先读取真实起始图像和指令，通过独立 Policy 调用模型，再严格检查它返回的动作，重建轨迹并调用官方指标。参考轨迹只在模型预测保存以后进入评分。每次请求、原始输出、预测动作和错误都单独保存，这样可以离线复算，不需要为了检查一个指标重复付费。当前真正运行的是 Qwen；Cosmos 是否能运行取决于对应路由和授权。

## 第6页

工程方面，我们保留了原来的九条流程实验，并固定官方代码版本。完整 seen 验证集已经通过哈希、图片解码和轨迹数量检查。当前对照集固定为一百条，开发集另外取十二条，并排除相同轨迹。需要说明，一百条来自冻结归档前缀，便于复用先导结果，它不是完整验证集均匀随机抽样。测试和运行记录保证结果可以追溯，但工程测试通过本身不等于模型性能提高。

## 第7页

现在磁盘中的真实状态是：基础版有效评估 100 条，优化候选有效评估 98 条。基础版总体 SR 为 5.0%，Score 为 11.04；候选版总体 SR 为 17.0%，Score 为 27.76。表中保留有效子集与失败记零的区别。API 成功不等于导航成功，失败也没有从分母中删掉。Prompt 只在独立开发集选择，再在相同的一百条做配对比较；即使没有提升，也保留负结果。

## 第8页

这里展示的初始图片、导航指令和两条曲线全部来自真实样本。蓝线是仅在评测阶段读取的参考轨迹，橙线是 API 输出动作积分得到的预测。即使路径的大方向看起来合理，转弯发生得过晚、总距离偏大或者停止位置不准确，都可能导致 SR 为零。若这页标题使用“最佳有效预测”，它只表示有合法输出，不代表已经导航成功。

## 第9页

我们把工程问题、模型误差和资源阻塞分开。基础版平均输出 9.1 步，参考平均 16.9 步，但逐例路径长度比平均达到 3.95 倍，说明步数少不等于走得短。尺度和停止位置偏差值得关注，转弯量也需要对照。这里是正式集事后解释，不用于同一正式集校准。候选策略已经先在独立开发集选定。Cosmos 授权和 LCVN 权重则是另一类资源问题，不能靠调 Prompt 解决。

## 第10页

最后，最短推进路线是先把当前授权实验完整做完，冻结配置并离线复算，再补齐 Cosmos 的合法授权，避免更换模型后却声称完成了同一对照。专用 LCVN 路线需要作者训练产物和明确 GPU 分配，先用三条样本验证加载与动作，再扩大规模。团队讨论最需要明确的是 Cosmos 授权由谁提供、LCVN 权重由谁联系，以及算力何时可分配。研究结论将建立在相同数据、完整失败统计和可复现记录之上。
